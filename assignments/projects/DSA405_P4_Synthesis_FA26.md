## Introduction

P4 incorporates elements from milestones 2 and 3. It also includes some additional documentation and reflection. 

These are the expected components of P4:

### 1. Reproducible notebook(s) on GitHub

The notebook runs from top to bottom on a restarted kernel, from the raw data to the
final figures, with no errors. It's okay if you have more than one notebook (some students will have one notebook for data extraction and another for data merging and cleaning).

### 2. Updated `README.md` on GitHub

A stranger should be able to read this file and understand how to run your analysis. The README should contain:

- A brief paragraph that says what the project is and what it found
- The data sources, with links and licenses
- How to run the project
- The structure of the repo, so a reader knows where each file is

### 3. The written report

The report can be submitted as markdown or Word. Here are the expected sections:

| § | Section | Contents |
|---|---|---|
| 1 | **Data motivation** | The question, why you chose it, and **how the question changed** once you had the real data (if applicable) |
| 2 | **Sources, provenance & terms** | For each source: who produced it, how it was collected, what it covers, its license, how you accessed it |
| 3 | **Data dictionary & metadata** | From P2. Updated to describe the **final** data |
| 4 | **Data cleaning steps narrative** | The path from raw data to final data. Explain the decisions you made along the way. |
| 5 | **Integration & verification** | How you joined your two (or more) data sources, and **how you verified that the result is correct** |
| 6 | **Findings** | What the project learned, with honest statements about what is uncertain |
| 7 | **What is missing** | The specific people, places, or cases the data excludes, and how each exclusion affects the conclusions |
| 8 | **AI use log & reflection** | Which tools you used, for which tasks, and surprises or reflections from using AI |
| 9 | **Reproducibility** | The repo link and instructions a stranger can follow |

**Length:** Word count is not graded. You can keep the sections brief, as long as all elements are present. 


**A few things to check about your repo**

- [ ] No API keys, tokens, or passwords committed anywhere in the repo's history
- [ ] Raw data saved in the repo, or a script included that downloads it
- [ ] Notebook(s) run without errors.
- [ ] Every claim in the report can be traced to something in the notebook
